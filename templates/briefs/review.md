# 지시서: 고객사 발송 전 독립 검토 세션 (읽기 전용)

`[ ]`를 채워 작업 세션에 그대로 준다. 이 SRS를 쓰지 않은 새 세션(새 문맥)에 맡긴다. 기준은 srs-kit STANDARD.md 10절과 9절 "보내기 전에"다.

## 목표
고객사에 보내기 전에 [페이지 묶음]이 코드, 결정 기록, 작성 기준과 맞는지 독립적으로 본다.

## 입력
- 페이지: [경로 목록] (기준 커밋 [SHA])
- 코드: [저장소, 브랜치]
- 결정 기록: [이슈 검색 조건, 사전 답변 목록 경로]

## 할 일
1. `srs check --base [기준]`을 돌리고 오류·경고를 유형별로 센다.
2. 페이지마다 아래 항목을 본다. 문제마다 페이지, 규칙 ID나 확인 요청 번호, 무엇이 틀렸는지, 고칠 문장을 쓴다.

| 항목 | 보는 것 |
| --- | --- |
| 사람 이름 | 고객사가 읽는 부분에 사람 이름이 남아 있다. 역할로 바꾼다 |
| 내부 ID | 업무 기록 번호, 이슈 번호, 내부 문서 번호, 메시지 ID가 있다 |
| `(제안)` 위치 | `(제안)`이 엉뚱한 행이나 엉뚱한 값에 붙었다. 내부 결정에 붙었다 |
| `(제안)` 근거 | `(제안)` 값의 근거가 확인 요청 "근거" 칸에 없다 |
| 질문 범위 | 확인 요청이 고객사가 정할 것(돈, 법·약관·개인정보, 고객사 운영, 다른 범위) 밖이다. 같은 결정을 두 곳에서 묻는다 |
| 질문 전제 | 질문의 전제가 지금 코드나 결정과 다르다 |
| 코드 대조 | 규칙이 지금 코드와 다른데 구현 상태에 없다 |
| 개발 근거 | 코드 경로·설명이 낡았다 |
| 이번 출시에 없는 것 | 사실이 아니라 영업 문구나 개발 제안을 쓴다 |
| 관찰할 수 없는 조건 | 시스템이 알 수 없는 사건을 조건으로 쓴다 |
| 영어 | 옛 메뉴 이름이 남았다. 화면 문구가 `"한국어" (English)` 꼴이 아니다. 고정 번역과 다르다 |
| 번호와 링크 | 확인 요청 번호가 바뀌었다. 링크 글자가 대상 페이지 제목과 다르다 |

## 보고서 형식
1. 기준 커밋, `srs check` 결과 개수
2. `| 페이지 | 위치(규칙 ID·질문 번호) | 항목 | 문제 | 고칠 문장 |`
3. 항목별 개수. 지난 검토에서도 나온 항목은 표시한다
4. 확인하지 못한 것과 이유

## 금지
- `docs/srs`·코드 수정, 커밋, push.
- 고객사·팀 채널 발송, 이슈 트래커 쓰기.

## 산출물
- 보고서 [경로]. 내용 작성 세션이 지적을 고친 뒤 보낸다.
