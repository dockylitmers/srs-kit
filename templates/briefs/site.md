# 지시서: SRS 문서 사이트 세션

`[ ]`를 채워 작업 세션에 그대로 준다. 기준은 srs-kit [`SITE.md`](../../SITE.md)(사이트가 갖출 것)다. 키트에 사이트 코드(`web/`)가 있으면 `web/README.md`도 본다.

## 목표
[앱 경로]에서 `docs/srs`를 SITE.md의 필수 항목(주소, 언어와 버전, 표시와 표, 열람 제한, 빌드)대로 보여 준다. 권장 항목 중 할 것: [몰아보기 / 고객사 코멘트 / 없음].

## 할 일
- **키트에 `web/`이 있을 때**
  1. `srs init <저장소> --web [앱 경로]`로 사이트 파일을 복사한다(있는 파일은 건너뛴다). 건너뛴 파일은 web/README.md의 설명대로 합친다.
  2. `features/srs-docs/srs-docs.config.ts`에 문서 주소, 사이트 제목, 기준 버전을 넣는다.
  3. `source.config.ts`의 frontmatter 스키마와 `srsVersions` 컬렉션을 합친다.
- **`web/`이 없을 때**
  1. 앱의 문서 도구(예: fumadocs)로 `docs/srs`와 `docs/srs-versions`를 읽는 컬렉션 두 개를 만든다. frontmatter는 `title`, `description`, `version`, `versionNote`, `status`, `code`.
  2. SITE.md 1절 주소 규칙으로 현재·번역·예전 버전 라우트를 만든다. 예전 버전은 요청 시 렌더링(5절).
  3. SITE.md 2~4절을 차례로 넣는다. 표시 배지와 표 규칙은 MDX 플러그인이나 CSS로 한다.
- 두 경우 모두 SITE.md 7절 확인 방법대로 확인한다.

## 완료 조건
- 프로젝트의 lint·type-check·테스트·빌드 통과. 현재 원문·번역은 정적 생성, 예전 버전은 요청 시 렌더링.
- 한국어 현재 페이지의 기존 주소가 그대로 열린다.
- SITE.md 7절 다섯 가지 결과가 보고서에 있다.

## 금지
- `docs/srs` 본문 수정(동작 확인용 임시 수정은 되돌린다).
- 계정 값을 코드 주석·문서·보고서에 쓰는 것(환경 변수로 둔다).
- 커밋·push·PR (승인 권한자가 한다).

## 산출물
- 작업 트리 변경(미커밋), 보고서 [경로]: 바뀐 파일, 검증 결과(명령과 결과, 캡처), 빌드 시간과 페이지 수, 남은 문제.
