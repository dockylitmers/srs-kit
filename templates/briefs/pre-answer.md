# 지시서: 사전 답변 목록 세션

`[ ]`를 채워 작업 세션에 그대로 준다. 기준은 srs-kit STANDARD.md 3.1절, 9절 "보내기 전에", PROCESS.md 4단계다.

## 목표
고객사에 보내기 전에 [페이지 묶음]의 확인 요청을 결정 담당(PM)이 빨리 답할 수 있는 번호 목록으로 만든다. PM이 정할 수 있는 것은 고객사 질문에서 빼기 위해서다.

## 입력
- 페이지: [경로 목록]
- 결정 기록: [이슈 검색 조건, 회의록 위치]
- 이미 받은 고객사 답: [고객 소통 도구 위치]

## 할 일
1. 페이지의 `(제안)`, `(준비 필요)`, 확인 요청 행을 모두 모은다. 표시가 없는데 출처도 없는 규칙도 모은다.
2. 항목마다 분류한다.
   - **고객사**: 돈, 법·약관·개인정보, 고객사 운영, 요청·계약과 다른 범위. 고객사에 그대로 묻는다.
   - **내부**: 그 밖의 구현 세부. PM이 정한다.
   - **이미 정함**: 결정 기록이나 고객사 답이 있다. 출처를 단다.
   - **전제 틀림**: 질문의 전제가 지금 코드나 결정과 다르다. 고칠 질문을 쓴다.
   - **중복**: 다른 페이지에서 같은 결정을 묻는다. 남길 한 곳을 정한다.
3. 아래 형식으로 목록을 만든다. 한 항목은 세 줄을 넘지 않는다. PM이 "번호: 답" 한 줄로 답할 수 있게 쓴다.

## 목록 형식
```
[번호]. [페이지 제목] (확인 요청 N 또는 규칙 ID) — 분류: [고객사/내부/이미 정함/전제 틀림/중복]
   질문: [한 줄]
   제안: [값] — 근거: [출처 또는 이유]
```

맨 위에 분류별 개수를 쓴다. 맨 아래에 답하는 법을 쓴다:
- "3: 제안값대로" — 제안값으로 정한다(내부면 내부 결정, 고객사면 제안값 그대로 묻는다)
- "5: 내부, [값]" — PM이 다른 값으로 정한다
- "7: 고객사" — 고객사에 묻는다
- "9: 삭제" — 질문을 지운다(번호는 "삭제"로 남는다)

## 완료 조건
- 묶음의 모든 표시·확인 요청 행이 목록에 있다(개수 대조 결과를 적는다).
- 모든 항목에 분류와 제안이 있다.

## 금지
- PM 대신 결정하기. 고객사·팀 채널 발송. `docs/srs` 수정(PM 답을 받은 뒤 정리판에서 고친다).
- 목록에 비밀값·개인정보 옮기기.

## 산출물
- 목록 파일 [경로]. PM 답을 받으면 같은 파일에 답을 적고, 정리판의 다음 판 목록으로 쓴다.
